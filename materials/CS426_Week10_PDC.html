Until now: parallel computing

  • Goal: finish one big job faster
  • Processors close together
  • Often share memory

From today: distributed computing

  • Goal: share resources and services
  • Computers can be far apart
  • They talk only by messages
💡 In simple words: Before, we used many processors to work faster. Now we use many computers in different places to work together as one service. You already saw message passing in MPI (Week 08).

What is a distributed system?

Tanenbaum & van Steen

"A collection of independent computers that appears to its users as a single coherent system."

Coulouris et al.

Parts on networked computers communicate and coordinate their actions only by passing messages.

TRY ITClick each key word to see what it means.

1 · Independent

Click
Each computer has its own CPU, memory and clock. It can work, or fail, on its own.

2 · Messages

No shared memory. Computers cooperate only by sending and receiving messages.

3 · One system

Click
The user does not see many machines. It feels like one service.
💡 In simple words: Many separate computers send messages to each other, and to you they look like one system.

Three key properties of every distributed system

1 · Concurrency

Many users and programs run at the same time and share things.

e.g. 500 students submit on the LMS at 11:59 pm

2 · No global clock

Each computer keeps its own time, and the clocks slowly drift apart.

So: who clicked first? Hard to say.

3 · Independent failures

One part can crash while the others keep running.

Others may not even know it crashed.

WATCHThree nodes, three clocks (live)

Node B is 0.8 s fast, Node C is 1.3 s slow. Which one shows the "real" time?

💡 In simple words: Many things happen at once, nobody has the exact same time, and one part can break without the others. These three facts make distributed systems hard.

Seven design goals

TRY ITClick each goal, one by one. Visited goals turn green.

Resource sharing

Let users use remote hardware, data and services as if they were on their own computer.

📁 A Google Drive file shared by a group · 🖨️ a network printer

Openness

Built on public, standard rules, so anyone can add new parts.

🌐 Any browser works with any website because both follow HTTP.

Transparency

Hide the fact that the system is spread over many computers.

🔗 You open au.edu.pk without knowing which machine answers.

Scalability

Keep working well when users, data or distance grow.

📈 Result day: 10 times more students than normal.

Concurrency

Many people use the same thing at once, and the result must stay correct.

✈️ Two people try to book the last seat.

Heterogeneity

Work across different devices, operating systems, networks and languages.

📱 Android, iPhone and Windows PCs all use the same service.

Fault tolerance

Keep the service running even when some parts fail.

🛟 One server crashes, a backup takes over.

💡 In simple words: These are the 7 things a good distributed system tries to achieve. Each one is also a challenge. Next, we look at the most important ones closely.

Transparency: what do we hide from the user?

TRY ITClick each type to see what it hides, with an example.

Access transparency

Hides: how a resource is accessed.

Example: You open a file on a network drive exactly like a file on your own disk.

Location transparency

Hides: where the resource is.

Example: www.youtube.com does not tell you the city or the machine.

Migration transparency

Hides: that a resource has moved.

Example: A website moves to a new data centre; its address stays the same.

Relocation transparency

Hides: that a resource moves while you use it.

Example: Your phone call continues while your phone switches towers on the motorway.

Replication transparency

Hides: that many copies exist.

Example: A video is stored on 50 servers, yet you see one video.

Concurrency transparency

Hides: that others use it at the same time.

Example: 300 students use the LMS together; each feels alone.

Failure transparency

Hides: that something failed and recovered.

Example: A server crashes; a backup finishes your payment.

Memory trick: "ALM RRCF"

Access · Location · Migration · Relocation · Replication · Concurrency · Failure

Hiding everything is not always possible or useful. Network delay cannot be hidden, and sometimes users must know, e.g. "Printer is offline".
💡 In simple words: Transparency means the user does not need to know the messy details: where things are, how many copies exist, who else is using them, or what broke.

Three ways a system grows

  • Size: more users and data
  • Geographic: users far apart
  • Administrative: many organizations

How we scale

  • Replicate: add more copies of servers
  • Partition: split the data and work
  • Cache: keep data near users

Failures and fault tolerance

TRY ITClick a server to crash it

Crash one, then two, then all three. Click again to repair.

⇅
✅ Service available · 3/3 copies up

Partial failure

Some parts fail, others still work. It is hard to tell "crashed" from "just slow".

How we handle it

  • Detect: timeouts, heartbeat messages
  • Mask: retry, keep extra copies
  • Tolerate: keep serving with fewer parts
  • Recover: logs, checkpoints, restart
💡 In simple words: Keep extra copies. If one breaks, another one answers, and the user never notices.

Myth or fact? Common mistakes

TRY ITEach red card is a myth. Click it to see the truth.

❌ "Distributed = parallel"

See the truth
✅ Parallel aims at speed; distributed aims at sharing across separate machines. They can overlap.

❌ "Client and server must be two machines"

See the truth
✅ They are roles. Both can run on one laptop (localhost).

❌ "A server is never a client"

See the truth
✅ An app server is a client of the database server.

❌ "More tiers is always better"

See the truth
✅ Each tier adds cost and delay. A small shop needs only 2 tiers.

❌ "Tiers and layers are the same"

See the truth
✅ Layers = software parts. Tiers = machines.

❌ "Hide everything from users"

See the truth
✅ Full transparency is not always possible or useful.
💡 Remember: These are the most common mistakes in exam answers. Avoid them!
