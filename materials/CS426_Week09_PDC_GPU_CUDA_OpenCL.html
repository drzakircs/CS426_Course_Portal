Recap · MPI versus GPU execution

Week 08 · MPI
  • Separate processes communicate via messages.
  • Processes may run on several computers.
  • Best for distributing work across processes or nodes.
Week 09 · GPU
  • Many lightweight threads execute device kernels.
  • Threads process many independent data items.
  • Usually controlled by a host CPU.
MPI and GPU are not opposites. Large systems may use MPI across nodes and GPUs within nodes.

CS-426 · WEEK 09SESSION 1 · GPU / GPGPUCONCEPT

Streaming Multiprocessors (SMs)

Inside one SM
  • Multiple execution lanes run threads.
  • Threads are scheduled in groups.
  • Registers and shared memory support execution.
Across the GPU
  • Several SMs execute blocks of work.
  • A grid may have far more blocks than SMs.
  • Hardware schedules blocks over time.
A CUDA block is a software work group; an SM is a hardware execution unit.

CS-426 · WEEK 09SESSION 1 · GPU / GPGPUCOMPARISON

Shared versus global memory

Shared memory
  • Visible to threads in the same block.
  • Fast on-chip storage.
  • Useful for cooperative tile calculations.
Global memory
  • Visible to GPU threads across blocks.
  • Large arrays live here.
  • Access patterns influence performance.
Threads in different blocks do NOT share one block’s shared memory.

CS-426 · WEEK 09SESSION 1 · GPU / GPGPUCONCEPT

Compute-bound or memory-bound?

Compute-bound
  • Arithmetic work dominates.
  • Improve useful compute throughput.
  • Example: many matrix operations.
Memory-bound
  • Moving/fetching data dominates.
  • Improve access patterns and reuse.
  • Example: simple scans over huge arrays.
GPU speed depends on BOTH computation and memory movement.

SIMD and SIMT · related but different

SIMD · architectural idea
  • One instruction acts on multiple data lanes.
  • A useful way to explain vector operations.
SIMT · CUDA execution model
  • Many threads run one kernel.
  • Threads may branch; divergence can reduce efficiency.
Do not treat SIMT as an exact synonym for SIMD.

What is CUDA?

CUDA
  • NVIDIA platform for GPU computing.
  • Exposes kernels, threads, blocks and grids.
  • Usually uses CUDA C++ or other CUDA-enabled tools.
Our learning example
  • Input arrays A and B.
  • One thread computes one output.
  • C[i] = A[i] + B[i].
CUDA is a programming platform, not a physical CPU or GPU architecture by itself.

CUDA vector addition · simplest kernel

CUDA C
__global__ void add(const float* A, const float* B,
                    float* C, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) {
        C[i] = A[i] + B[i];
    }
}
This is a CUDA C++ device kernel. One thread computes one C[i].

CS-426 · WEEK 09SESSION 2 · CUDA / OPENCLCONCEPT

OpenCL · another GPU programming framework

OpenCL
  • Open cross-platform heterogeneous compute standard.
  • Supports compatible CPU, GPU and other device implementations.
  • Kernels execute as work-items in work-groups.
Important difference
  • CUDA is tied to NVIDIA’s platform.
  • OpenCL uses a platform/device discovery model.
  • Device availability depends on drivers and implementation.
OpenCL is not restricted to one particular GPU manufacturer.

CS-426 · WEEK 09SESSION 2 · CUDA / OPENCLMISCONCEPTION CHECK

Common misunderstandings · correct them

“GPU always faster.”Transfer/setup and workload size matter.
“One block = one core.”Block is logical; SM is hardware.
“All GPU threads share fast memory.”Shared memory is scoped to a block.
“OpenCL equals CUDA.”They are distinct programming platforms.
Correct models prevent programming errors and unrealistic performance expectations.
